    About

    VeloxQuant-MLX control panel

    What this is

    A local front-end for veloxquant serve. It spawns the same command you could type yourself and reports what that process announces — it never runs inference in its own process.

    How to read the numbers

    measured comes from the running process — psutil RSS and MLX's own memory counters. These are facts.

    estimate comes from the cache's byte counters. Compression is currently accounting-only: caches store dequantized fp16, so these measure compression fidelity, not memory saved. The two are not comparable.

    Telemetry coverage is uneven. Of the servable methods, some report keys and values, some report keys only, and eviction methods report no byte counters at all — they drop tokens rather than compress bytes. The Methods tab shows which applies. Where nothing is reported, this panel says so rather than showing zero.
